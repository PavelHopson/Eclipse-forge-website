# Интерактивный обзор проектов

Откройте [index.html](index.html) в браузере из рабочей копии. Поиск, фильтры, описания и карта кода работают без сервера, установки пакетов, аккаунта или внешних запросов. Для локального HTTP-просмотра достаточно статического сервера, ограниченного этой папкой.

Это **обзор репозиториев, не панель мониторинга production**. Кнопка GitHub ведёт к исходному репозиторию, а не обещает наличие неопубликованной документации. У локальных проектов без origin внешняя кнопка отсутствует.

## Навигация и первый шаг

Выбранный проект, направление и поиск сохраняются в hash-части адреса: обновление страницы восстанавливает состояние, «Назад/Вперёд» возвращают описание или список без потери позиции. Текст поиска не отправляется HTTP-серверу. Кнопка «Ссылка на проект» копирует только проект, без поискового текста и фильтра; для file:// и loopback показано, что ссылка локальная.

Блок «Первый шаг» выбирает объявленную dev-команду и показывает её папку и manifest. Для .NET, Python-бота, сетевых утилит и Library используется маршрут по README, без выдуманной npm-команды. Копирование ничего не выполняет, не устанавливает зависимости и не доказывает работу приложения.

Поиск учитывает несколько слов, ё/е и некоторые русские окончания; это локальное сопоставление текста, не семантическая модель.

## Источники и обновление

- Описание и границы: [редакционные профили](../../scripts/repository-profiles.mjs).
- Индивидуальные входы в README и команды старта: [repository-readme.mjs](../../scripts/repository-readme.mjs); локальные обложки: [repository-cover.mjs](../../scripts/repository-cover.mjs).
- Карта файлов и названия команд: текущие checkout, прочитанные [генератором](../../scripts/repository-presentation.mjs).
- Общая стратегия и зрелость: [канонический реестр](../eclipse-forge-os/projects/README.md). Здесь они не переопределяются.
- [Визуальная и security-приёмка](design-review.md) · [Статус задачи и точные результаты проверок](release-check.md).
- Проверить воспроизводимость: `node scripts/repository-presentation.mjs --check` из корня Landing.
- `--apply` изменяет документацию нескольких репозиториев и требует осознанного выбора этой задачи. По умолчанию генератор ничего не меняет. Он использует явный allowlist, проверяет Git-корни и не заменяет существующие файлы другого владельца.

### Защита повторной генерации

Перед первой записью проверяется весь план, а перед каждой операцией — текущий снимок файла. Квитанция предыдущей генерации хранит hash управляемой области: всего гайда/SVG, только вступления README или только навигации у проектов с сохранённым оформлением. Ручное изменение управляемой области блокирует перезапись. Техническое тело README и изменившиеся версии в сохранённых вступлениях не становятся собственностью генератора.

При отсутствии квитанции существующий отличающийся файл не импортируется автоматически. Квитанцию можно установить для уже совпадающих с генератором файлов: проверенный запуск `--apply` в этой задаче завершился с `filesChanged: 0`. Не удаляйте квитанцию ради обхода конфликта — сначала сравните изменения. Каждый завершённый запуск сохраняет отдельный журнал; исходный baseline не пересоздаётся.

Это не атомарная транзакция между 36 репозиториями: поздняя параллельная запись может остановить пакет после ранее выполненных операций. Проверяйте diff и результаты остановившегося запуска, не откатывайте чужую работу автоматически. Доказательства этой задачи исключены из Git точным правилом `.gitignore`.

README теперь содержат собственные разделы «Проект за минуту» и «Начать локально» внутри управляемых маркеров. Заголовки внутри этого блока не становятся началом пользовательского технического текста. У проектов с сохранённым hero меняется только этот блок. Точные исправления устаревшего текста в восьми README учтены отдельными хеш-квитанциями третьего прохода; старый baseline не подменяется.

`node scripts/test-repository-readme.mjs` проверяет 36 README, источники, ссылки и сохранность текста относительно начала третьего прохода. С заданными путями `REPOSITORY_MARKED`, `REPOSITORY_PLAYWRIGHT`, `REPOSITORY_EDGE` он также рендерит Markdown на 390/1440 px без внешних ресурсов. Это локальное приближение к GitHub Markdown, не скриншоты опубликованных репозиториев. HTML-превью и результаты остаются в игнорируемых артефактах задачи.

Проверки: `node --test scripts/test-repository-write-guard.mjs`, `node scripts/test-repository-portfolio-browser.mjs` и `node scripts/test-repository-presentation.mjs`. Браузерный тест требует путей к уже установленным Playwright и Edge; последний скрипт использует локальный начальный baseline и отдельно сигнализирует о параллельных изменениях документации. Он не является CI всех продуктов.

## Безопасность и доступность

Статические локальные данные выводятся через textContent; HTML из данных не исполняется. Внешние ссылки разрешены только на HTTPS-репозитории github.com, без учётных данных, нестандартного порта и query-параметров. Копируемые команды ограничены объявленными npm script names и допустимыми папками. Нет API, uploads, analytics, localStorage, service worker, платных операций или командного исполнителя. Clipboard используется только по кнопке; отказ браузера показан человеку, а завершение старой операции не меняет заново открытое окно.

Предусмотрены загрузка, ошибка повреждённого каталога, пустая выборка, сброс фильтров, disabled-состояния, клавиатура, Escape, возврат фокуса и reduced motion. StarCRM/StarMarket, дубли и сторонние форки исключены.

Дизайн использует цвета Eclipse visual-system v1 и системные шрифты. Новых изображений сторонних авторов, шрифтов или зависимостей нет. Диаграммы в README — собственные SVG-схемы, а не скриншоты работающих приложений.
