# Визуальная и security-приёмка

Дата: 2026-09-08. Профиль: **product / repository index**. Состояние: локальная приёмка; публикация и пользовательское подтверждение ещё не выполнены. Это не изменение adoption-статуса основного сайта Eclipse Forge.

## Доработка навигации и первого шага

- Отдельные ссылки на проекты, восстановление после reload, Back/Forward, позиция списка и focus. Hash содержит состояние только на клиенте; копируемая ссылка не содержит поискового текста.
- Видимый тип проекта в строке и первый шаг в описании. Команда сопровождается реальной папкой и источником; для другого стека не подставляется npm. Кнопки только копируют текст.
- Русский поиск допускает несколько распространённых окончаний, ё/е и несколько слов. Не заявляется полноценный morphological/semantic search.
- На телефоне вторичные действия расположены рядом, основное — отдельно. Touch controls не меньше 44 px; sticky-кнопка закрытия остаётся доступна.
- Первый dev-шаг — дополнительная справочная секция, не второй продуктовый CTA и не execution console. AS-01–AS-25 решения ниже сохраняются; новые декоративные эффекты и изображения не добавлены.
- 58/58 браузерных сценариев после доработки; отдельно 14/14 тестов генераторной защиты. Desktop/mobile окна первого шага просмотрены визуально. Нет новых внешних запросов и page errors.

## Задача и основной путь

Найти подходящий репозиторий, понять назначение и открыть исходники. Основное действие — выбрать строку проекта; в описании — открыть GitHub. Поиск и направления видны сразу, техническая детализация раскрывается по желанию. Трёхсекундный тест оценён по интерфейсу автором изменений; отдельного исследования с новым пользователем не было.

GitHub README не исполняет JavaScript. Поэтому репозитории получили обычную Markdown-навигацию и статические SVG, а интерактив вынесен в отдельный локальный HTML-каталог.

## Происхождение и нагрузка

Цвета взяты из Eclipse visual-system v1. Иллюстрации — собственные SVG-схемы маршрутов; шрифты системные. Нет новых библиотек, удалённых картинок, CDN, аналитики или фоновых сетевых обращений. Production bundle основного сайта не менялся: новый интерфейс находится в docs/portfolio и не подключён к runtime маршрутам.

## Пропорциональная security-проверка

Использована применимая часть conducting-api-security-testing: минимизация публичных данных, проверка входа и безопасный вывод. Его offensive-сценарии и исполняемые сканеры не запускались.

- Данные выводятся только через textContent/createElement; raw HTML не принимается.
- Ссылки проходят HTTPS/github.com allowlist, без credentials, query и fragment; для новых вкладок noopener/noreferrer.
- CSP запрещает connect, формы, объекты и посторонние скрипты; страница не выполняет команды из каталога.
- Нет секретов, внутренних checkout-путей, приватных remotes, IP инфраструктуры или содержимого окружения в публичном catalog.js.
- Нет auth, API backend, uploads, storage, OAuth, платежей, обновления зависимостей или production-конфигурации в изменённой поверхности.
- Новые публичные файлы проверены ограниченным поиском высоковероятных credential-сигнатур. Это не полноценный secret scan истории и не аудит CVE всех продуктов.

Доработка обнаружила и закрыла **Low: риск случайной публикации локальных доказательств** — каталог с baseline, внутренними checkout-путями и screenshots ранее был untracked, но не ignored. Добавлено точное правило только для артефактов этой задачи; git check-ignore подтверждает его, git ls-files не содержит этих файлов. Фактическая публикация этих данных не обнаружена и не заявляется.

Новых Critical / High / Medium находок в проверенной поверхности не выявлено. Добавлены bounded parsing адреса, allowlist копируемых команд и защита от устаревшего clipboard feedback. Генератор проверяет содержимое до записи и сохраняет квитанции владения; это не filesystem sandbox и не межрепозиторная транзакция. Описанные в гайдах риски отдельных продуктов не считаются устранёнными этой задачей. Доступность GitHub-репозиториев, CI и работа production-сервисов отдельно не проверялись.
