# Stage 0 public evidence inventory

## Evidence boundary

This inventory is the complete allowlist for the first positioning audit. It was
assembled from the public Landing repository and public URLs on 2026-08-07. “Verified”
means the cited statement is present in the repository snapshot; it does not prove
customer demand, uptime, production usage or commercial results.

No secret value, private repository, customer record or authenticated analytics source
was opened.

## Claim decisions available before the run

| Candidate claim | Decision | Reason |
| --- | --- | --- |
| Eclipse Forge is a multi-product engineering ecosystem | verified | The public manifest enumerates products with distinct roles and repositories |
| Eclipse Forge OS is an observable, bounded Agent Office program | partially verified | Contracts and components are documented; flagship end-to-end readiness is explicitly incomplete |
| Chat, AI Hub, Library, Sentinel and Media already operate as one production platform | rejected | Several integrations are `planned` or `experimental`; the manifest does not support a unified production claim |
| Eclipse Forge has customers, revenue, conversion lift or proven PMF | unverified | No allowlisted source contains this evidence |
| Eclipse Forge OS replaces a team or guarantees income | rejected | No evidence supports the claim and it conflicts with the product boundary |
| All listed projects are production-ready | rejected | The manifest explicitly labels beta, prototype, library and live states separately |

## Evidence gaps

- No independently verified customer problem interviews.
- No accepted end-to-end Growth Office run with cost and editing time.
- No public case study connecting an artifact to a qualified business action.
- No attributable analytics baseline.
- No evidence yet that the phrase “human-controlled AI operations workspace” is
  understood or preferred by the target audience.

These gaps become experiment inputs. They must not be converted into positive claims.
