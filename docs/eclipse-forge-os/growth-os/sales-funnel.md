# Одна воронка первых продаж студии

**25.11.2026, Claude.** Сводит в одну воронку записи реестра 00-006, 00-007, 00-024, 00-145, 10-004, 30-020, 40-009, 50-023 и лид-магнит «Где теряются заявки». Решения ниже — предложения; цену, получателя заявок и ответственного выбирает Павел.

Факты на 25.11: продаж по «Одной рутине» и Automation Audit в чатах нет; оплаченного пилота студии нет; форма на живом сайте ничего не отправляет (копирует текст и открывает Telegram).

## 1. Что было: два оффера на одну аудиторию

| | «Одна рутина» / AI Automation Audit (Кодекс, 20·Соцсети, 00·Координатор) | «Где теряются заявки» (Claude, PR #20) |
|---|---|---|
| Что обещает | Описать один повторяющийся ручной процесс → аудит одного процесса | Самопроверка за 15 минут: 12 проверок, где бизнес теряет заявки |
| Сегмент | Малый бизнес с любой ручной рутиной (гипотеза, не подтверждён) | Малый бизнес, которому нужны заявки: гостевые дома, услуги |
| Платный шаг | Аудит 5 рабочих дней; гипотеза 25–50 тыс. ₽, в финмодели 35 000 ₽ (10-004) | Тариф «Сайт с заявками» от 30 000 ₽, «Сайт + система заявок» от 70 000 ₽ — уже на лендинге |
| Материалы | Бриф, карта рутины из 12 полей, OR01–OR07 (черновики), таблица метрик, UTM | PDF-чек-лист, пост-закреп, сценарии шортов A и B |

**Вывод.** Вход в воронку — «Где теряются заявки»: боль конкретная, проверка делается за вечер, следующий шаг уже есть на лендинге (тарифы + демо). «Одна рутина» не выбрасывается: обработка входящих обращений — одна из её рутин, а формат аудита (карта процесса, до трёх вариантов автоматизации, решение «пилот / собрать данные / не автоматизировать») становится форматом **разбора** заявки. Остальные пять направлений из 00-007 и 00-145 (линейка инфопродуктов, white-label, корпоративная Library, Media Studio) — после первой оплаты, не параллельно.

## 2. Один оффер

**«Разбор: где теряются ваши заявки» → пилот «Сайт с заявками»**

Клиент получает:
1. Разбор за 24 часа по его чек-листу и ответам формы: где именно теряются заявки, что чинить первым.
2. Созвон 30 минут: откуда приходят заявки, что из этого закрывает сайт.
3. Предложение пилота: сайт (или редизайн по демо) + заявки в Telegram/MAX/почту + Метрика. Состав и срок — в смете до начала работ, работа — после «да» клиента.

Для гостевых домов пилот начинается с демо-редизайна их текущего сайта (как договорено в пилоте студии); на лендинге и в материалах город не упоминаем.

**Цена пилота — решение Павла:**

| Вариант | Цена | Плюс | Минус |
|---|---|---|---|
| **A. Разбор бесплатно, пилот по тарифу** | 0 ₽ разбор → «Сайт с заявками» от 30 000 ₽ | Минимальный порог; цены уже на сайте, ничего не переписывать | Время на разбор не оплачивается; риск «просто посоветоваться» |
| **B. Платный экспресс-разбор, засчитывается в пилот** | гипотеза, например 5 000 ₽ → вычитается из 30 000 ₽ | Отсекает несерьёзных; разбор оплачен | Ещё один шаг оплаты до первого клиента; цена не проверена |
| **C. AI Automation Audit одного процесса** | 35 000 ₽ по финмодели 10-004, 5 рабочих дней | Готовые материалы Кодекса | Дороже тарифа на сайт; не подтверждён ни одной продажей; сложнее объяснить |

Рекомендация: **A** до первого оплаченного пилота — по реестру цель сейчас «один реальный клиент до предложения пилота», а не маржа. После 2–3 разборов пересмотреть в сторону B.

## 3. Один путь

```
Шорт B / пост-закреп в @EclipseForgeEngine
  → PDF «Где теряются заявки» (12 проверок)
  → в конце PDF: «Пришлите результат» → eclipse-forge.ru/?utm_source=…&utm_campaign=lost-leads-2611#contact
  → форма контакта: 5 полей + согласие → «Отправить заявку»
  → relay на VPS (/api/lead) → получатель: Telegram-бот ИЛИ почта
  → ответственный отвечает в течение 24 часов: разбор
  → созвон 30 минут → предложение пилота (смета, срок)
```

| Шаг | Что считать | Где видно | Статус |
|---|---|---|---|
| Шорт / пост | просмотры, переходы | YouTube, Telegram | сценарии готовы, публикует Павел |
| PDF | скачивания из закрепа | Telegram | PDF готов, ждёт закреп |
| Лендинг | визиты с `utm_campaign=lost-leads-2611` | Яндекс Метрика | ссылка на PDF и UTM — бэклог №7 |
| Форма | отправленные заявки | получатель заявок | код готов (PR), включается после выбора получателя |
| Разбор | ответ ≤ 24 ч | переписка | нужен ответственный |
| Пилот | согласованная смета | договорённость | — |

Заявка с UTM приходит получателю строкой «Источник: utm_campaign=…» — так видно, что сработало, без отдельной CRM.

Альтернативный вход без сайта (остаётся): сообщение в Telegram @EclipseHopson с результатом чек-листа.

## 4. Получатель заявок: два варианта до кнопки

Код один для обоих: `server/lead-relay/` — маленький сервис на Node без зависимостей, слушает `127.0.0.1:8787`, Caddy проксирует на него `/api/lead`. **Получатель меняется одной настройкой `LEAD_RECIPIENT`** (`telegram` | `email` | `stub`) в файле окружения на VPS; сайт пересобирать не нужно. Отправка на сайте включается один раз сборкой с `VITE_LEAD_ENDPOINT=/api/lead`; без неё форма работает по-старому. Защита: проверка Origin, согласие обязательно, лимиты длины, 5 заявок с IP за 10 минут, ловушка для ботов, повтор той же заявки не дублируется, ответ сервера не повторяет данные клиента. Тесты: `tests/lead-relay.test.mjs` (9 сценариев, на заглушках, без реальных ключей).

| | **(а) Telegram-бот** | **(б) Почта** |
|---|---|---|
| Что нужно от Павла | 1) создать бота в @BotFather → токен; 2) нажать «Start» в боте со своего аккаунта (или добавить бота в рабочую группу); 3) `chat_id` — подскажу команду, токен вписывает сам Павел в файл на VPS | 1) ящик-получатель; 2) SMTP-ящик-отправитель (например, Яндекс) и пароль приложения; 3) на VPS `npm i nodemailer` в `server/lead-relay` |
| Работа | ~1 час: файл окружения, systemd-сервис, 3 строки в Caddyfile, сборка с `VITE_LEAD_ENDPOINT`, релиз, тестовая заявка | ~1,5 часа: то же + установка nodemailer + проверка, что письмо не в спаме |
| Скорость реакции | Уведомление на телефоне сразу | Зависит от того, как часто проверяется почта |
| Риски | Доступ VPS к api.telegram.org — проверить `curl` до запуска; утечка токена → отозвать в @BotFather за минуту; Telegram — иностранный сервис (см. ниже) | Хостер может закрывать SMTP-порты; письма в спам; пароль приложения — такой же секрет, как токен |
| Совпадает с тарифом на сайте | Да: «Заявки в Telegram, MAX или на почту» — свой сайт становится живым примером | Да |

Общее для обоих:
- **Персональные данные.** Форма собирает имя и контакт. До включения на проде нужна страница политики обработки данных (бэклог №4) и ссылка на неё у галочки согласия. Требование 152-ФЗ о первичной записи данных россиян в базе на территории РФ — проверить; если нужно, relay может дописывать копию заявки в файл на VPS (одна настройка, сделаю по «да»). Это вопрос к юристу, не вывод.
- **Секреты** только в `/etc/ef-lead-relay.env` (права 600), не в git и не в сборке сайта.
- **Заглушка `stub`** пишет заявки в файл на VPS — только для теста маршрута, не для работы: её никто не читает.

Рекомендация: **(а) Telegram** — Павел живёт в Telegram, тариф обещает клиентам то же самое, ответ за 24 часа проще держать по уведомлению.

## 5. Кто отвечает клиенту

Нужен один ответственный за ответ ≤ 24 часов и разбор. Варианты: Павел сам; Павел + черновик разбора от агента (Кодекс/Claude) по чек-листу, отправляет Павел. Агенты клиентам сами не пишут.

## 6. Готово, когда

По реестру (лист «Приоритеты»): одна реальная заявка прошла путь форма → получатель → ответ ответственного → согласованный результат пилота. Оплата учитывается по факту.
